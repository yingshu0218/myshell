# MyShell 整体开发说明

## 1. 产品定义

MyShell 是一个个人使用的跨平台终端系统，包含：

- **Docker 网页端**：部署在 VPS，通过浏览器提供容器 Shell 和 SSH 终端。
- **macOS 客户端**：Swift 编写的原生终端，支持 Zsh 和 SSH。
- **Windows 客户端**：原生终端，支持 PowerShell、CMD、WSL 和 SSH。
- **中转服务**：负责登录认证、加密数据同步、状态检查和备份调度。

第一阶段将网页端和中转服务放在同一个轻量 Docker 容器中，但代码模块保持
分离。未来原生客户端通过版本化 HTTPS API 接入同一中转服务。

## 2. 数据流与备份

中转服务是唯一的日常同步通道：

```text
macOS / Windows / Web
          ↕ HTTPS
中转服务（认证、同步、状态）
          ↓ 可选备份
GitHub 或 Gitea 私有仓库
```

GitHub/Gitea 不参与实时同步，只保存加密快照，用于灾难恢复。备份支持手动、
每日或每周执行；恢复必须由用户确认，不得自动用旧数据覆盖当前数据。

## 3. 强制开发顺序

### 阶段一：Docker 网页终端与中转服务

1. Go 服务骨架、配置加载、文件存储和健康接口。
2. 单用户初始化、账号密码登录、会话和登录限速。
3. PTY 会话、容器 Shell、SSH 子进程和资源回收。
4. 浏览器终端、多标签页、连接列表和响应式布局。
5. 连接保险库、加密存储和同步 API。
6. 手动/定时检查中转服务及 SSH 目标在线状态。
7. GitHub/Gitea 加密备份、列表和确认恢复。
8. `reset-password` 与 `show-account` 本地管理命令。
9. Docker 镜像、安全加固、长时间测试和性能验收。

### 阶段二：macOS 客户端

网页/中转验收后，使用 SwiftUI/AppKit、系统 PTY、Zsh 和 OpenSSH 开发原生
客户端，并接入已稳定的同步 API、状态检查模型和加密格式。

### 阶段三：Windows 客户端

macOS 稳定后开发 Windows 原生客户端，支持 PowerShell、CMD、WSL 和系统
OpenSSH，并复用公共协议与数据格式。

## 4. 第一阶段技术架构

- **进程模型**：一个 Go 服务进程，同时托管 API、静态网页和终端会话。
- **前端**：原生 HTML/CSS/JavaScript，不使用大型前端框架。
- **存储**：原子写入的版本化文件；个人单用户阶段不预先引入数据库。
- **终端**：后端创建 Linux PTY，运行容器 Shell 或系统 SSH；浏览器与后端
  使用双向流式连接交换输入、输出和窗口尺寸。
- **同步**：版本化保险库 API，支持拉取、条件更新和冲突响应。
- **调度**：仅在用户配置定时检查或备份时运行，限制并发并加入超时。

## 5. 认证与密码恢复

服务首次启动后通过初始化页面创建唯一管理员账号，随后永久关闭初始化入口。
不提供注册、多用户、邮件找回或双因素认证。

最低安全要求：

- 只保存加盐密码哈希。
- 公网部署强制 HTTPS。
- 登录失败限速并短暂锁定。
- 使用 HttpOnly、Secure、SameSite 会话 Cookie。
- 会话具有空闲和绝对过期时间。
- 修改或重置密码后注销所有会话。

VPS 管理员可执行：

```bash
docker exec -it myshell myshell-server reset-password
docker exec myshell myshell-server show-account
```

重置命令交互输入两次新密码，密码不得出现在参数或 Shell 历史中。

## 6. 保险库与同步安全

连接保险库包含服务器地址、端口、用户名、密码、分组和显示设置。磁盘、网络
及 Git 备份中只允许出现加密数据。恢复密钥通过只读 Docker Secret 挂载，
不得写入镜像、源码仓库、普通环境变量或日志。

同步写入使用版本号或 ETag 进行条件更新。版本冲突必须返回双方版本，由客户端
明确解决；禁止最后写入者静默覆盖密码。网络失败不影响已有终端会话。

## 7. 状态检查

界面分别显示：

- 中转服务状态：健康、版本、延迟和最后同步时间。
- SSH 目标状态：主机、端口可达性、延迟、超时和最后检查时间。

支持检查单台、检查全部及 5/15/30/60 分钟定时检查。SSH 状态检查只测试目标
端口，不执行登录。调度器限制并发；状态变化可在网页内提示，不长期保存大量
监控历史。

## 8. 低资源约束

- 单进程、按需创建会话，不运行无意义的常驻任务。
- 对滚动历史、输出缓冲、并发终端、状态检查和重试设置上限。
- 终端关闭后立即回收 PTY、SSH 子进程、文件描述符和内存。
- 前端增量渲染，后台标签页降低刷新频率。
- 性能判断基于生产构建和真实容器测量。

首个原型建立启动时间、空闲 CPU、基础内存、每会话内存、镜像大小和吞吐基线，
之后每项性能敏感变更提供前后数据。

## 9. 第一阶段非目标

不实现多人账户、团队权限、插件市场、AI 功能、SFTP 文件管理、集群调度、
复杂监控平台、移动客户端或主题市场。

## 10. Web/中转完成标准

- 公网 HTTPS 下账号登录、退出、限速和密码重置通过测试。
- 容器 Shell 与 SSH 会话可稳定创建、交互、调整尺寸和关闭。
- 连接资料只以密文保存，同步冲突不会丢失数据。
- 手动和定时状态检查正确，空闲时无额外轮询。
- GitHub/Gitea 备份与确认恢复各完成真实测试。
- 容器重启后数据可恢复，未产生孤儿进程或文件描述符泄漏。
- 自动化、安全及长时间测试通过，并记录资源基线。

满足全部条件后，才开始 macOS 客户端实现。
