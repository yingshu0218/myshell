# Sync Hub 接入决策

本文记录 MyShell Web 接入 Sync Hub `v0.1.0`
（固定提交 `7b5038c15fb87158de4bbd43d7fb510c7a52521e`）时会影响跨端兼容、
数据迁移或安全边界的决定。状态为“待确认”的项目不得固化到生产数据格式。

## DEC-20260726-01：本地与 Sync Hub 数据来源

- 状态：已接受（项目所有者于 2026-07-26 确认）
- 背景与代码证据：`internal/vault/vault.go` 已将完整保险库以 AES-256-GCM
  密文原子写入 `/data/vault.json`；当前没有同步状态存储。
- 备选方案：只支持在线；Sync Hub 取代本地文件；本地保险库作为离线副本。
- 建议决定：保留现有加密 JSON。`local` 模式以本地保险库为唯一数据源；
  `sync-hub` 模式以 Sync Hub 为跨设备真源，本地保险库作为可离线使用的加密副本，
  本地修改进入有界持久化待上传队列。停用同步不删除本地数据。
- 安全影响：Sync Hub Token 只从只读 Docker Secret
  `/run/secrets/sync_hub_token` 读取；普通配置只保存 API 地址、app/device ID 和模式。
- 迁移影响：首次启用必须先拉取远端，再明确选择上传本地独有记录或采用远端记录；
  两侧同 ID 内容不同时不得静默覆盖。
- 测试要求：本地独立运行、断网读写、重启恢复队列、停用同步后数据保留。

## DEC-20260726-02：第一版同步范围与记录映射

- 状态：已接受（项目所有者于 2026-07-26 确认）
- 背景与代码证据：`vault.Data` 当前包含 `Connections`、`Preferences` 和
  VPS 专属的 `Backup` 配置；连接记录已有稳定字符串 ID。
- 建议决定：

  | 本地对象 | 是否同步 | collection / recordId | 说明 |
  | --- | --- | --- | --- |
  | SSH 连接 | 是 | `connections` / 现有 UUID | 每台服务器一条记录，包含用户名和密码明文后再由记录信封整体加密 |
  | 外观偏好 | 是 | `terminal-profiles` / `default` | 只含主题与代码预览开关 |
  | Git 备份配置 | 否 | — | 属于当前 VPS，不应覆盖其他设备 |
  | 健康状态、终端会话、日志 | 否 | — | 仅运行态，可能含敏感终端信息 |

- 删除语义：连接删除生成 Sync Hub tombstone；本地保留已确认删除版本，不能仅从
  数组移除。
- 兼容影响：现有非 UUID 连接 ID 在启用同步前拒绝并提示修正，不自动改 ID。
- 测试要求：公共 schema、删除传播、未知字段和未知 schema 安全拒绝测试。

## DEC-20260726-03：跨端加密信封 v1

- 状态：已接受（项目所有者于 2026-07-26 确认）
- 背景与代码证据：现有 `myshell-aes-256-gcm-v1` 信封加密整个本地保险库，
  AAD 只绑定本地版本，不能直接作为独立同步记录格式。
- 建议决定：新增独立的同步信封，不修改现有本地保险库格式。算法使用 Go 标准库
  AES-256-GCM；每次加密生成 12 字节随机 nonce。AAD 使用 UTF-8 严格拼接：
  `myshell-sync|v1|{appId}|{collection}|{recordId}|{schemaVersion}`。
-  Sync Hub `payload` 承载 `0x4d 0x53 0x01 || nonce || ciphertext || tag`，`checksum` 为该 payload 的
  SHA-256 base64url 值，用于传输前快速损坏检测；GCM 仍是安全完整性边界。
- 密钥模型：与 Sync Hub Token 分离，第一版 Web 从现有 `vault_key` Docker Secret
  读取同一 32 字节主密钥；Sync Hub 永远不接收密钥。
- 兼容影响：在 `shared/crypto/envelope-v1.md` 固定字节格式，并生成跨语言正向、
  错误 AAD 和损坏密文测试向量后才实现网络上传。
- 测试要求：固定 nonce 测试向量、随机 nonce 不重复、篡改失败、1 MiB 上传前限制。

## DEC-20260726-04：冲突与首次切换

- 状态：已接受（项目所有者于 2026-07-26 确认）
- 建议决定：非秘密字段仅在一侧相对共同基线变化时自动三方合并；同字段双改进入
  冲突。密码只要两侧均变化就必须由用户选择，不允许 last-write-wins。
  首次切换先执行只读预检并显示“仅本地、仅远端、冲突”数量；用户确认后才写入。
- 状态持久化：原子写入 `/data/sync-state.json`，保存不透明 cursor、每条记录的
  服务端 version、tombstone、最多 500 个待上传操作及其 Idempotency-Key。
  Token、主密钥、明文、密文和完整响应不得进入该文件或日志。
- 错误处理：`401/403` 停止自动同步；`409` 保存冲突供 UI 处理；传输错误与 `5xx`
  有界退避并复用原幂等键；`400/413/422` 不盲目重试。
- 测试要求：双设备并发、密码冲突、超时幂等重试、分页失败不提交 cursor、
  无效 Token 停止重试。

## 实施门禁

项目所有者确认上述四项后，按以下顺序实施：

1. 先提交公共 schema、加密信封规范和固定测试向量。
2. 实现标准库 Sync Hub HTTP 客户端和原子同步状态存储。
3. 实现单设备拉取、上传、tombstone、离线队列与契约测试。
4. 最后增加设置页的数据来源切换、预检、手动同步、状态和冲突处理。

任何第三方依赖、旧数据 ID 自动迁移或加密格式变更仍需另行获得明确批准。
